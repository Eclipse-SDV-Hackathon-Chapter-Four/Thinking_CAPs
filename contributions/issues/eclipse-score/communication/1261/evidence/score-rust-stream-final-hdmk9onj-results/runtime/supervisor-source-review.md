## Semantic and verification findings

**S4 — Allocation and callback bounds are overstated.** `service_stream.rs:22–28` and native implementation notes C7 call the leak/buffering bounded by configured types/currently offered instances. `queue: VecDeque` (line 106) has no capacity, backpressure or overflow policy; `apply_snapshot` appends each new availability transition (approximately 174–179). One repeatedly withdrawn/reoffered identity can accumulate arbitrarily many unconsumed entries, independent of the current offer count. Each open also retains its callback `Arc` through the inherited empty dispose hook, and therefore potentially retains that queue after stream drop. Callback processing does not test `finished`; the comment that no callback is expected after stop is not established by native stop. `ServiceDiscoveryClient::StopFindService` (`bindings/lola/service_discovery/client/service_discovery_client.cpp:267–281`) only adds the handle to `obsolete_search_requests_`; callback/watch deletion is deferred to `TransferObsoleteSearchRequest` (331 onward). Do not equate a stop request with callback quiescence or allocation-policy compliance. No immediate free/UAF is asserted here: retaining the callback and Runtime-owned deployments avoids that particular reclamation hazard.

**S5 — An added unit test depends on unordered iteration.** `service_stream.rs:322–331` assumes newly reported instance 1 precedes instance 2. The implementation constructs a `HashSet` and iterates `current.difference(&previous)` (approximately 144–165); no order is guaranteed. This can make the test fail nondeterministically without a deduplication defect. Seven added mock cases are statically present; no executed count is claimed.

**S6 — The real integration assertions are not discriminating for every advertised obligation.** `consumer_app.rs:72–81` accepts at least two BigData items and one MixedPrimitives item with BigData provider ID 2 appearing twice. Duplicate callbacks before withdrawal can satisfy that criterion; it neither observes a withdrawal boundary nor asserts exact deduplication, version, binding, binding service ID or MixedPrimitives ID. Provider sleeps (2s/2s/1s) have no startup/stream-open handshake, so initial versus delayed discovery is not demonstrated relative to stream creation. No initial-empty phase is asserted. `consumer_app.rs:121,135,138` uses `std::process::exit`, which skips stack destruction and does not exercise the actual stream Drop/stop path. The distinct consumer/provider manifests genuinely discriminate provider ID 2 absent from the consumer’s BigData instance configuration, and two actual generated interfaces are used; these positive properties do not fill the other gaps. The Python case is one proposed native integration test, not six cases or a system-wide proof.

**S7 — Applicability remains narrower than unqualified system-wide discovery.** `runtime.cpp:305–343` enumerates only configured types having instance entries, groups by full `ServiceIdentifierType`, and retains the first chosen instance deployment’s quality and permission context. Types with no instance entry, unconfigured interfaces, non-LoLa bindings and configuration additions after the first cached enumeration remain outside the stream. ## Positive architecture observations and remaining limits

The proposal now contains an actual LoLa override and FFI/backend code rather than only a public default returning NotSupported. Full owned descriptor identity includes type name, major/minor version, binding, binding service ID and observed concrete instance ID; it does not fabricate an InstanceSpecifier. Per-watch complete snapshots plus global reference counts aim to suppress unchanged/overlapping identities and permit reoffer after final withdrawal. Shared callback state exists before watch start; successful handles are owned before return, never-polled Drop stops each owned handle, and partial-start failure stops earlier watches. Stops are issued outside callback membership locks. AtomicWaker registration followed by queue recheck addresses the ordinary lost-wakeup window. These are static design observations, not measured race/cancellation guarantees.

Their member order precedes binding/service-discovery ownership, avoiding the initially considered per-stream borrowed-deployment lifetime problem.
