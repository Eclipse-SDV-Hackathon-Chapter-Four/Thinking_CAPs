# Readiness and campaign contract
Success requires native `get_world`, with a fresh client for each failed startup attempt.
Use an absolute Linux monotonic deadline and cap each RPC timeout to remaining time.
Server exit is a startup failure. TCP/version alone do not establish physical readiness.
CARLA plant becomes ready before diagnostic watchdog/controller startup; startup unknown
checks still run before publishing. Keep the original timeout/debounce/occurrence expectations.
Physical campaign cannot publish fixture speed; actual receiver speed, moving actor, applied
native return request and the full native lifecycle must satisfy explicit acceptance.
