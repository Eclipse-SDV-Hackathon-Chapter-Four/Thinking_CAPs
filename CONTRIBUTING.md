# Contributing

Use the destination project's contribution guide and pinned toolchain. Preserve
original patches, notices, failed runs and source-bound evidence. Add corrected
submission artifacts separately; revalidate affected checks when source changes.

Native Eclipse commits must use the responsible human's legal name and account
email. Each author/committer needs applicable agreement coverage. Jefferson's
Eclipse username is `jnascimento6p0`; this does not cover other contributors.
Supply a truthful DCO sign-off when the destination requires it.

Disclose meaningful AI assistance in PRs and commits. Use `Assisted-by` for tools,
with known provider/model details. AI tools are not human coauthors. Largely
generated files need project notices and an AI disclosure; follow the destination's
file-level treatment. Preserve copied code's original licences. Check input rights
and applicable provider terms before using external services.

Retain reviewer identity, revision and decision. AI output requires human review;
critical changes need another team member's review. Record required native checks
and dispositions for omissions. Project committers determine net new IP and
engage Eclipse's IP Team when required. No official merge before required approvals.

See the [Eclipse handbook](https://www.eclipse.org/projects/handbook/),
[current compliance record](contributions/shared/compliance/2026-10-07/README.md), and
[contribution inventory](contributions/README.md). Local test success is distinct
from upstream acceptance and competition eligibility.
